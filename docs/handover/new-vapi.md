# Rebuilding on a new Vapi account

Everything the agent is lives in this repo. Vapi holds a *copy* that was pushed
from here, so moving to another account is a rebuild, not a migration — you run
the same scripts against a different key and then fix the ids that other files
point at.

Read this once before starting. The rebuild is about twenty minutes. **Two steps
fail if you have not done the work below first (step 0 and step 5), and one step
fails silently (step 2).**

Last verified against the live account on **7 Aug 2026**.

## Before you start: two blockers

**1. The Cartesia credential does not travel, and losing it makes no noise.**
The Hebrew voice is Cartesia Eyal. Cartesia needs its own API key registered on
the Vapi account — the current account holds exactly one credential and that is
it. A new account has none. `vapi_sync.py` will push a Cartesia voice with a
`vapi/Elliot` fallback, so **the call still connects and the agent still talks —
in an American accent.** Nothing errors, nothing logs, and Vapi's cost records
report `voiceId: Elliot` for that provider regardless of what was spoken, so the
bill will not catch it either. The only symptom is that it sounds wrong to
somebody who speaks Hebrew.

The 11labs transcriber (`scribe_v2_realtime`) needs **no** credential — it is
billed through Vapi. Cartesia is the one exception, and it is the one that
matters.

**2. The English twins cannot be regenerated from the Hebrew today, so they are
copied instead.** `vapi_en.py` requires every substitution in its table to match
the live Hebrew prompt exactly once and exits rather than shipping a
half-translation. The debt table's stale entries were fixed on 7 Aug and the
counts are now explicit, but **109 Hebrew passages in the prompt still have no
English pair** — the prompt went from 33k to 63k characters and most of that
growth is prose quoting Hebrew. The intake table has 9 stale entries from the
מיכל → מיכאל change.

So step 5 copies the existing English assistants across verbatim rather than
rebuilding them. They are complete, working assistants — but they were last
regenerated at **02:54 on 7 Aug** and carry none of that day's fixes. **Do not
use an English twin to judge whether a Hebrew fix worked.** Check where the
rebuild stands at any time:

```
python scripts/vapi_en.py debt --dry
python scripts/vapi_en.py intake --dry
```

## What is actually stored where

| | Source of truth | Vapi's copy |
|---|---|---|
| Debt prompt (he) | `docs/features/10-debt-followup/prompt.md` | pushed by `vapi_sync.py debt` |
| Debt prompt (en) | generated by substitution | pushed by `vapi_en.py debt` |
| Intake prompt (he) | `docs/assistant/demo-inbound.md` | pushed by `vapi_sync.py inbound` |
| Intake prompt (en) | generated by substitution | pushed by `vapi_en.py intake` |
| The eight debt tools, the three intake tools | `scripts/vapi_tools.py` | pushed with the assistant |
| Voice, transcriber, endpointing, end-call phrases | `scripts/vapi_sync.py` (`BASE`, `TARGETS`) | pushed with the assistant |
| The end-of-call report endpoint and its secret | `.env` (`SUPABASE_URL`, `TOOL_SECRET`), via `report_server()` | `server.headers`, and **redacted in the export** — restore it by re-running `vapi_sync.py --apply`, never by copying the JSON |
| The spoken-output filter | `scripts/voice_guard.py` | `voice.chunkPlan.formatPlan.replacements` |
| Resident data | the Google Sheet | never stored in Vapi |
| Tool execution | n8n → Apps Script | Vapi only holds the webhook URL |
| **Provider API keys** | **nowhere in this repo** | **Vapi's credential store — see blocker 1** |

**Nothing of value is only in Vapi except the Cartesia key.**
`docs/handover/vapi-export.json` records what the account held on the day it was
written — regenerate with `python scripts/vapi_export.py`. It cannot be pushed
back: Vapi mints new ids on create, so the export is for reading, not restoring.

**Archive the current export by hand before re-running it on a new account.** The
script writes to a fixed path and will otherwise destroy the only record of the
account you just left. The convention in this folder:

| File | Account |
|---|---|
| `vapi-export.json` | whichever account is current |
| `vapi-export-account2-05aug.json` | the 5 Aug–7 Aug account, as it stood at the 7 Aug move |
| `vapi-export-old-account.json` | the original account, as it stood on 5 Aug |

## What does not come across at all

- **Call history, transcripts and recordings.** They stay behind. Recordings are
  deleted after 14 days regardless, so pull anything you still want *first* —
  `scripts/vapi_leak_check.py <call-id>` prints a transcript, and the stereo
  recording is at `artifact.presignedStereoUrl` on `GET /call/<id>`.
- **Provider credentials.** Re-add the Cartesia key by hand.
- **The eval suite.** Recreate with `python scripts/vapi_eval.py --setup`.
  Deliberately not part of the rebuild: it creates billable resources.
- **The duel resident** (`vapi_duel.py --setup`). Same reason.
- **`Riley`** — not ours. Every new account arrives with one; the id differs each
  time, so do not grep for the old one.
- **Anything edited in the dashboard and never written back here.** Diff the new
  assistant against `vapi-export.json` if you are unsure.

There is **no phone number** on the account and none to move. Web calls from the
demo page need none, which is how all testing has been done since 4 Aug.

## The rebuild

**0. Fix the two blockers above.** Then continue.

**1. Create the account** and copy both keys from Dashboard → Organization →
API Keys. You need the **private** key for the scripts and the **public** key for
the browser page.

Put the private key in `.env` — never on a command line, never in chat:

```
VAPI_PRIVATE_KEY=<the new private key>
```

**2. Add the Cartesia credential.** Dashboard → Provider Keys → Cartesia, paste
the Cartesia API key. **Do this before the first push, not after**, because an
assistant pushed without it sounds fine and is wrong. Verify:

```
python scripts/vapi_export.py --show      # a `credential` line with cartesia in it
```

**3. Push the two Hebrew assistants.** Each creates by name when nothing matches,
so this is the same command that updates them:

```
python scripts/vapi_sync.py debt          # dry run — read this before applying
python scripts/vapi_sync.py debt --apply
python scripts/vapi_sync.py inbound --apply
```

Write down both ids. Check the `voice :` line of the output says
`cartesia a976c076…` and not `vapi Elliot` — that is the one-line version of
blocker 1.

**4. Repoint `SOURCE` in `scripts/vapi_en.py`** to step 3's Hebrew debt id
**before** running step 5. The twin is built from the *live* Hebrew assistant, so
on a stale-but-valid key it would silently build from the old account's prompt.
On a wrong key it fails cleanly with a 404.

**5. The two English twins.** If `--dry` is clean, regenerate them:

```
python scripts/vapi_en.py debt --create
python scripts/vapi_en.py intake --create
```

If it is not clean — which is the case today, see blocker 2 — copy the existing
ones across instead. Read both from the old key, strip the server's own fields,
POST to the new one:

```python
READ_ONLY = {"id", "orgId", "createdAt", "updatedAt",
             "isServerUrlSecretSet", "latestVersion", "version", "credentialIds"}
body = {k: v for k, v in old_assistant.items() if k not in READ_ONLY}
```

`latestVersion` is the one that is not obvious — Vapi returns it and rejects it,
with a 400 that names the field.

**Never do this for a Hebrew assistant.** They rebuild from the markdown in
seconds and a copy would be a fork of the source of truth.

**6. Repoint everything that hardcodes an id.** This is the step that breaks
things, because a wrong id does not error — it starts a call with the wrong
agent, or with one that no longer exists.

| File | What to change |
|---|---|
| `web/index.html` | `ASSISTANTS.he` (line 334), `ASSISTANTS.en` (line 335), `PUBLIC_KEY` (line 329) |
| `scripts/vapi_en.py` | **two** source ids — debt and intake. Step 4 covers the debt one; the intake one is beside it |
| `scripts/vapi_call.py` | `ASSISTANT_ID`, `PHONE_NUMBER_ID` |
| `scripts/vapi_duel.py` | `MICHAL_ASSISTANT`, `MICHAL_NUMBER_ID` |
| `scripts/vapi_eval.py` | `MICHAL_ASSISTANT` |
| `scripts/vapi_mock.py` | `SOURCE` |
| `web/README.md`, `docs/assistant/*.md` | the ids quoted in prose |
| `docs/features/04-interruption-pacing/feature.md` | quotes the intake id — easy to miss, it is the only `docs/features/` file that does |

Find every one of them:

```
grep -rn "3303317e\|7449bc9a\|86a01f13\|3edbe85b\|ddd7e209" \
  --include=*.py --include=*.html --include=*.md .
```

Those five are the current values — debt (he), debt (en), intake (he),
intake (en), public key. Earlier accounts used `56935b35`, `731193bf`,
`a594a4ce`, `27382abf`; grep for those too if something still misbehaves.

**`web/index.html` is its own git repository**, `TheSuperShyy/homies-voice-demo`,
which auto-deploys to Vercel on push. It is not a file you upload. Bump `BUILD`
in the same commit — the status bar shows it, and it is the only way to tell from
the browser whether the page in front of you is the one you just changed.

**7. Verify before trusting it.** In order, because each step assumes the last:

```
python scripts/vapi_export.py --show      # four assistants, right names, cartesia credential
python scripts/check_tools.py             # the tools answer, writes land
python scripts/vapi_leak_check.py 20      # nothing spoke its own machinery
```

Then place one web call from the page and confirm all of:

- **it sounds Israeli.** Blocker 1 has no other symptom.
- the status bar shows the `BUILD` you just pushed
- it identifies the resident from the sheet, not the built-in fallback
- it never mentions a card
- it never says a tool name, a field, or anything with an underscore in it
- it ends the call itself, on `endedReason: assistant-said-end-call-phrase`
- a row appears in `payment_links`
- a row appears in `call_outcomes` — if this is missing, the closing ended the
  call before the outcome was logged, which has regressed before
- **a row appears in `interactions`, with a transcript and a `latency_ms`.**
  Added 8 Aug. This one is checked last because it arrives last — the end-of-call
  report fires after the call has ended, not during it. Empty means the `server`
  block did not survive the rebuild, and there is no other symptom: the call
  itself sounds perfect and nothing anywhere errors.

## The rest of the system, which is not Vapi's

A new Vapi account changes nothing here, but if the whole thing is being moved:

| Piece | Where it lives | Moving it |
|---|---|---|
| Tool routing | n8n workflow `Homies — debt tools (Vapi)` | `python scripts/n8n_deploy.py --apply --activate` |
| Call queue read | n8n workflow `Homies — call queue (read)` | `python scripts/n8n_queue.py --apply --activate` |
| Data + tool writes | Apps Script bound to the residents sheet | paste `sheets/Code.gs`, set `HOMIES_SECRET` in Script Properties, redeploy, copy the new `/exec` URL into `.env` and both n8n scripts |
| Test console | `web/index.html` | its own repo → Vercel, see step 6 |

The n8n instance is **shared production carrying other clients' workflows**. Only
ever create there; never modify, activate or delete anything that is not ours.

If the n8n instance changes, the webhook URL changes, and **that** has to go back
into `scripts/vapi_tools.py` and be pushed to Vapi again — otherwise the new
assistants call the old instance and every tool silently writes to the wrong
place.

## Things that are wrong today and should not be copied forward

- **The n8n webhook is not checking its secret.** `N8N_WEBHOOK_SECRET` is set in
  `.env` and the assistants send `x-homies-secret`, but the workflow does not
  verify it, so anyone with the URL can write rows. Check it in the Code node.
- **Seven credentials have been pasted in plaintext across sessions** and none is
  confirmed rotated. The n8n JWT has no expiry and can read, modify and delete
  every workflow on that shared instance. Rotate before any real Homies data
  touches this.
- **The Vapi public key is committed in `web/index.html`** in a private repo, and
  the page is live on Vercel. It can start calls that bill to the account, so the
  URL must not be posted publicly.
- **The English twins are stale by design of the process, not by accident.** Any
  edit to a Hebrew fixed line breaks them, and they are only rebuilt when someone
  remembers. If English is going to be the language demos are given in, that
  needs to be a step in the push, not a separate script somebody runs later.

silent Elliot fallback and re-synced without complaint.

`.gitignore`; check that before you make one.
