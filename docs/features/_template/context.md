# <Feature name> — context

## Why this exists

The problem in the real world, not the ticket. Who suffers today, and how.

## Decisions

Each decision, what it rules out, and the reason. Format:

**<The decision>.** Why. What was rejected and why that alternative loses.

The test for whether a decision belongs here: would someone arriving in three
months be tempted to change it back? If yes, it belongs here.

## Constraints

External facts we do not control — vendor behaviour, language, regulation,
client environment. Distinguish these from decisions. A constraint cannot be
argued with; a decision can.

## Known failure modes

Ways this is expected to break, and what we do about each. Written before it
breaks, so the first incident is recognised rather than investigated.

## Open questions

Things genuinely unresolved. Each with what would settle it. Delete entries as
they are answered rather than marking them resolved — this file is a working
document, not a changelog.

## Related

Links to the spec, other features, and the schema this touches.
